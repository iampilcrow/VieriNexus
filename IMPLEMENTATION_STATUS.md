# VieriNexus implementation status

## Foundation implemented

- One Dalamud plugin package with separate Domain, Application, Contracts, and Plugin assemblies.
- Polished dark/red/gold application shell based on the supplied visual direction.
- Branded VieriNexus Home experience using the supplied logo; no temporary splash window.
- All Nexus windows remain hidden until a targetable character has settled in the world.
- Mandatory dependency setup gate with six core required providers and a separately labeled recommended-integration catalog audited from every current Vieri product.
- Dependency health detection and focused Install/Enable/Manage actions through Dalamud's plugin installer.
- Nine neutral built-in module registrations, including Routes & Navigation.
- Read-only discovery of all nine predecessor configuration sources, including VieriNavPlotter.
- Transactional Routes & Navigation importer with full setting/route mapping, validation preview, timestamped source backup, atomic Nexus-owned staging, SHA-256 receipt, newer-data rollback guard, and restoration of the prior Nexus state. Import never changes the standalone source or activates duplicate navigation.
- The Migration card sizes action buttons from their rendered labels, stacks them when the available width is too small, wraps status/detail text, and scales its panel height with the configured UI scale. A zero-personal-route import explicitly confirms that settings were still imported.
- A saved navigation receipt is reloaded and verified against its source ID, exact Nexus target path, target SHA-256, schema, and staged payload after Nexus is disabled/re-enabled. The exact staged message and rollback availability are reconstructed without opening or changing VieriNavPlotter.
- A dedicated Routes page keeps verified migration staging read-only, then explicitly creates a separate Nexus-owned working library. The working file is atomically replaced and retains its previous complete version. Nexus can create a route at the current position; time movement capture with configurable interval/spacing; add, replace, reorder, remove, undo, reverse, or safely clear points; edit name/tags/notes and movement settings; duplicate and exchange compatible route JSON; search, inspect, persistently preview in the world, travel to point one, play all points in order, Stop, and confirm deletion without modifying VieriNavPlotter or its migration receipt.
- Timed recording is a non-moving observer and owns no automation resources. It filters nearby samples, saves each accepted point atomically, refreshes active preview, and stops on territory change, missing route/character, logout, or unload. Clipboard imports are bounded and validated, receive a new identity, and cannot enable an imported automation assignment.
- Recording controls, capture interval, and minimum spacing are grouped in one `Record & edit route` section. Display preferences, metadata/automation, vendor templates, troubleshooting, and infrequent route actions are separately categorized and collapsed. The route list/editor create no nested scrolling region and expand under the page's one outer scrollbar. Clear-points and delete-route confirmations share the buttons' UI scope so both dialogs open reliably before any destructive edit.
- The Staged Settings panel measures its height from the active text metrics and padding, keeping every imported preference visible at supported interface scales instead of clipping the final row.
- A pure navigation activation policy and runtime assessment report working-library, source-plugin, dependency, Navigation/Movement lease, Stop, manual-override, and reload-reconciliation gates. VieriNavPlotter loaded means Nexus pauses; otherwise ready prerequisites activate route authority automatically.
- An idempotent navigation Stop coordinator holds the tracked execution lease across unavailable providers, rejected Stop calls, unknown confirmation, and still-active movement. Its vnavmesh adapter sends `vnavmesh.Path.Stop` and separately reads `vnavmesh.Path.IsRunning`; only an explicit inactive result releases Navigation/Movement ownership. Natural completion uses a separate observation-only release and does not send a global Stop.
- The normal Routes page replaces the former activation/safety workflow with one compact Ready or Paused line; detailed provider health remains available under Troubleshooting.
- A manual-movement safety coordinator now observes FFXIV's configured movement actions instead of assuming fixed keys. Remapped keyboard movement, mouse steering, gamepad movement, jump, and autorun block new starts. Input during a future tracked execution latches verified Stop, retries while movement remains active, and stays paused after confirmation until an explicit resume acknowledgement following the character's quiet period. Disabling the character protection setting while an execution is tracked also fails closed and stops it.
- Manual-movement observation runs every plugin draw, including while the Nexus window is closed, and interrupts both direct Nexus route movement and every phase of a Nexus-dispatched suite trip through verified Stop.
- A minimal atomic navigation-intent journal records execution/route/lease identity and state before direct local provider movement, deliberately storing no resumable instruction pointer. Reload and shutdown reconciliation stop first and confirm inactivity without replaying; corrupt or unwritable intent blocks activation.
- Resource lease expiry is retained for an every-draw watchdog even when another acquire, snapshot, or late heartbeat discovers it first. An expired tracked Navigation/Movement lease latches verified Stop and cannot restart automatically.
- Navigation authority becomes available automatically after VieriNavPlotter is unloaded and every safety gate is ready. Nexus never toggles the source plugin, and every movement start still atomically acquires Navigation/Movement after rechecking the boundary.
- The single route execution entry gate rechecks source/safety state, current-character authorization, manual-input quiet time, territory, and provider readiness; atomically acquires Navigation and Movement; journals no-replay intent; and registers verified Stop before invoking vnavmesh. It heartbeats the lease, observes completion, and exposes guarded UI plus `/nexus play <name>` and `/nexus stop`. Source reappearance, provider loss, or a conflicting owner revokes authority fail-closed.
- Shared-vnavmesh destination ownership is checked while moving. If another plugin replaces the Nexus path, Nexus records the execution as superseded and releases only its own lease without issuing Stop, preserving VieriCodex/AutoDuty/other-provider movement.
- The provider-neutral planner produces immutable Review, Travel to Start, and Playback plans with validation, exact ordered points, route distance, same-territory execution gating, flight/tolerance settings, and no side effects.
- Live navigation-provider health now covers the vnavmesh Stop contract, manual movement observer, reload/watchdog reconciler, VieriNavPlotter ownership, the atomic Navigation/Movement bundle, and Nexus authority. These observations populate shared world state and a bounded session-only transition audit without storing credentials or logging every frame.
- An explicit non-moving simulation runs six production-coordinator scenarios against isolated memory-only state: guarded start/verified Stop, manual takeover, no-replay reload, provider loss/retry, source-owner return, and lease expiry. Its provider has no movement operation and the simulation cannot touch live ownership or the live journal.
- User Stop confirms inactivity, releases ownership, and completes its no-replay checkpoint immediately. After manual takeover, the next explicit Play/Travel request clears the stopped latch once the manual-input quiet period has elapsed; no separate acknowledgement UI is required.
- Communications discovery is existence-only: VieriLink's encrypted token, channel IDs, status message ID, and command cursor are not opened, decrypted, logged, copied, or rewritten by the current build.
- Route migration requirements preserve searchable names, stable IDs, notes, tags, ordered points, territory, playback settings, and explicit assignments without enabling disabled overrides.
- VieriNavPlotter's visible built-in baseline includes all 27 current AutoDuty gear-vendor destinations and distinguishes Domitien's authored multi-point approach from destination-only navmesh behavior.
- Route migration now explicitly preserves the review and execution controls: persistent in-world Show Route previews, Travel to Start/Destination, complete point-by-point Play Route, cross-zone AutoDuty travel ownership, and a working Stop Playback path.
- All 27 verified VieriAutoDuty gear-vendor standing-point routes are compiled into an immutable Nexus catalog and can be copied into the personal working library without touching the source. Copies receive a new identity, remain editable, and start with automation disabled. A route can capture the current target without enabling itself; explicit approval enables exactly one route per territory/vendor target and atomically disables a competitor. While Nexus owns navigation, VieriAutoDuty 1.0.0.440 prefers the versioned Nexus resolver, then safely falls back to VieriNavPlotter and its built-in routes.

VieriAutoDuty enters the requested inn through the correct innkeeper, preserves the complete trip across both loading transitions, then plays the route's authored points. Its route Stop is idempotent, so an already-inactive trip is safely confirmed without asking the user to open AutoDuty. ## Intentionally not enabled yet

- Routes parity is implemented pending a focused inn-trip smoke check: same-zone, cross-zone, and Grand Company inn Play/Travel prefer consistent whole-trip suite travel, with guarded direct vnavmesh as same-zone fallback. Current-target binding, immutable vendor templates, exact-target Gear consumption, ownership-filtered live waypoints, authoring, recording, editing, exchange, static preview, and immediate Stop/restart are present. The suite adapter tracks only work Nexus explicitly dispatches, manual movement stops the entire dispatched trip, and unrelated AutoDuty or vnavmesh movement is never adopted.
- No Discord credential, channel, or message ID has been read or changed.
- No existing Vieri plugin has been disabled, uninstalled, or modified.
- No duty/progression/combat/HUD/market/communications automation has been enabled. Only explicit Nexus route actions are live.
- Dependency actions open Dalamud at the exact plugin entry; Nexus does not yet call Dalamud's private installer internals.
- Migration-source products remain excluded from the permanent third-party dependency catalog. VieriCodex remains authoritative during migration; the approved end-state moves its Vieri-specific layers into Nexus and uses stock Questionable through a capability-versioned external-provider adapter for ordinary supported quests.
