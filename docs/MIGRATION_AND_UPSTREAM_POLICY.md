# Migration and upstream policy

## Non-negotiable migration rules

1. Existing Vieri configuration files and directories remain untouched during discovery and import.
2. An importer writes a timestamped backup before creating Nexus-owned state.
3. Import happens into a staging model, validates, then commits atomically.
4. A failed import leaves the old product authoritative and Nexus inactive for that module.
5. Every setting receives an explicit mapping, intentional retirement reason, or compatibility default.
6. Character-owned data is keyed by content ID and world, not character name.
7. Discord secrets are never logged or included in support exports. Encrypted tokens move only on the same Windows account and remain encrypted.
8. Standalone plugins are not disabled or uninstalled automatically.
9. A migrated module must pass behavior, configuration, IPC, and rollback tests before becoming authoritative.
10. Progression-to-combat migration must retain the corrected solo-duty handoff from VieriCodex 1.12.2.76: begin a fresh rotation automation session on duty entry, keep selected-target behavior primary, enable nearest-hostile action targeting only after a sustained targetless gap, yield immediately when normal targeting recovers, expire every fallback assist automatically, never rewrite the player's hard target, and leave movement exclusively to the encounter provider.
11. Quest-route migration must retain VieriCodex route corrections over downloaded upstream data. In particular, every resumable Dravanian Hinterlands approach for `Sage's Focus` (accepted, duty-ready, and post-duty sequences 5, 6, and 8) must request flight when it is unlocked.
12. Manual Gear shopping must remain a complete transaction: Nexus owns the visible item/slot review, exact single-use approval, maximum prices, gil reserve, and full Teleport/Navigation/Movement/UI/Inventory lease; honor that approval, purchase only the selected upgrades, equip and verify every approved replacement with one idempotent retry, update the current gearset, then transfer every newly displaced weapon, armor piece, and accessory from the Armoury Chest into normal inventory before releasing the Gear lease. Any changed character, job, equipment signature, item, quantity, or higher price invalidates the approval before movement. Across every job and every automatic, manual, native, or Gearsetter recommendation source, an off-hand is invalid while the effective main-hand weapon is two-handed; the main hand must be planned and equipped first so valid one-handed weapon plus shield sets remain supported without permitting failed shield retries. Every automatic/manual gear-shopping, selling, repair, card-exchange, and GC turn-in route uses FFXIV's native interaction predicate. A distinct authored standing point must be completed before interaction eligibility may end travel; only a raw NPC-coordinate route may stop early when native interaction becomes valid. If the NPC object is unavailable, a conservative 3.1-yalm coordinate fallback may apply on the final approach. Long same-territory vendor travel must prefer an unlocked destination-region aetheryte over a hazardous cross-zone navmesh run, while final vendor legs under 100 yalms remain on foot; a walking request must never mount merely because flight is unlocked. Vendor travel must never declare success when native interaction reports out of range, skip authored points, push into collision, or enter avoidable stall/repath recovery. Existing EXP-item and sell/desynth protections remain mandatory.
13. Until Nexus is authoritative for a module, a published fix to any predecessor Vieri product is not complete until Nexus pins that exact source revision and records the applicable behavior or regression requirement. Nexus may not claim runtime ownership before the corresponding embedded module and tests exist.
14. VieriNavPlotter migration must retain every custom route exactly: stable ID, name, notes, tags, ordered coordinates, territory, playback flags, tolerances, and explicit consumer assignments. A disabled override must remain disabled after migration.

16. Route review and playback parity is mandatory: every built-in and personal route must expose Show Route, Travel to Start/Destination, Play Route, and Stop Playback. Complete routes follow all saved points in order; destination-only entries remain labeled as generated navmesh approaches. Cross-zone execution must use the suite travel owner so teleport, Aethernet, flight, navmesh, and stall recovery do not compete. Built-in vendor playback and destination travel must preserve the vendor target ID and trusted NPC coordinate through the suite IPC so the shared final-approach interaction stop remains active; a multi-point Travel to Start must omit that final-vendor completion metadata. Nexus may render the complete live waypoint chain only while NavPlotter playback/travel owns navigation or the suite explicitly authorizes gear-shopping travel; ordinary Goto commands, inn travel, duties, and unrelated vnavmesh users must remain hidden. Existing visualization owned by outside plugins remains untouched.
17. Route authoring parity includes a horizontally resizable route-library pane and an always-available current-position inspector that displays and copies territory plus full-precision X/Y/Z coordinates.
18. Market migration must retain VieriAutoMarket's ownership-aware pricing and verified one-pass execution. Exact matching to another owned retainer must wait until the comparison window is closed and settled, write through the game's numeric price control, send the complete confirmation event expected by `AddonRetainerSell`, and verify the saved price before continuing. Automatic reference selection must detect a suspicious low-price cluster activated by a 1-gil listing (for example, `1, 5, 10,000` selects `10,000`), use the next logical external or owned-retainer reference, and leave the listing unchanged when no safe reference exists.
19. Rotation suggestion overlays must respect native FFXIV UI occlusion per icon. Single-target, AoE, and dynamic suggestions may not draw over maps, inventory, action bars, or other native windows; occlusion must not mutate rotation decisions, prediction timelines, hotkeys, positioning, or saved layout.
20. Migration discovery for a source containing protected credentials is existence-only until that source's dedicated encrypted-value adapter and same-account round-trip tests are present. Generic discovery, preview, diagnostics, and support export code may never deserialize VieriLink's encrypted token, channel IDs, status message ID, or command cursor.
21. Progression migration must retain VieriCodex 1.12.2.79's Questionable 15.756.0.0 integration: 7.56 MSQ routes 5475-5478, Beastmaster routes 5490-5491, Beastmaster quest/category mapping, and the VieriCodex live-gearset selection policy. Quest acceptance must refresh current gearsets, filter them through `CodexActivityPolicy`, and guard an empty acceptable-job result before indexing it; a later upstream merge may not restore the unchecked `acceptableJobs[0]` path.
22. Custom UI migration must retain VieriDelvUI 2.8.0.0's Beastmaster HUD visibility/configuration/role mapping and current distance/party-ready-check API handling without replacing Vieri identity, commands, profiles, highlighting, nameplate stacking, integrated native enemy markers, Duty Support companion roles, or saved settings.
23. Progression migration must retain VieriCodex 1.12.2.80's Questionable 15.756.0.1 integration: quest 5492 `Hearts Aligned`, its level-16 override and Beastmaster class switch, the Bastion placeholder mapping, current Allied Society validation metadata, and enabled Boss Mod handoff for quest 5476 `A Rush of Cold Wind`. The existing live-gearset refresh, eligibility filter, empty-result guard, solo-duty targeting lease, and named-route behavior remain authoritative Vieri customizations.
24. External-provider updates are integrated by contract audit, not by copying their implementations into Nexus or rebuilding unaffected consumers. The verified Boss Mod 7.5.6.0 and Lifestream 2.5.4.21 commits and compatibility findings remain pinned in `upstreams/source-lock.json`; any later provider update must revalidate every consumed endpoint and identifier before release.
25. Built-in vendor templates are immutable reference data, not automatically active routes. Copying one into the Nexus working library must create a new stable identity and keep its override disabled. Enabling an exact territory/vendor assignment must atomically disable any other enabled route for that same pair. Resolution is read-only, starts no movement, and fails closed when the assignment is absent, invalid, or ambiguous; consumer dispatch still enters through the normal resource and navigation safety gates.
26. VieriAutoDuty is a migration source, not the permanent duty provider implementation. Nexus owns Vieri-specific route/travel, progression-loop, Last Run, gear/inventory, maintenance, telemetry, command, and UI behavior; stock AutoDuty owns its native supported-duty engine behind a module-scoped capability/version adapter. Generic duty fixes are upstreamed or proven present with contract/replay fixtures. The fork cannot retire until the complete inventory and gates in `AUTODUTY_PROVIDER_MIGRATION_AUDIT.md` pass.
27. Class/Job/Role quest selection belongs to Nexus. Nexus resolves the applicable stable game-data chapter families, asks the active Questionable-compatible provider only for locked/ready/accepted/completed state, pins one exact quest ID, and invokes `StartSingleQuest` for that ID. Completion requires the same ID to be complete and the provider to be inactive. Stock Questionable's published IPC names are the permanent boundary; fork-only broad progression queues, activity selection, UI, and policy must not become a Nexus dependency.
28. A second user or computer migrates locally: install Nexus while that computer's predecessor configurations still exist, run its own verified setup, and only then disable replaced products. Never package or copy another user's character IDs, routes, profiles, progression state, or secrets as defaults.
29. Progression migration must retain VieriCodex 1.12.2.81's Questionable 15.756.2.4 integration: current quest/gathering routes including the missing Kugane side-quest set, interaction-wait combat handling, class-switch safeguards, Aetheryte/Unlocks journal behavior, and standardized provider health detection. The Vieri live-gearset eligibility filter and empty-result guard, Progress Atlas, Progression Queue, named routes, solo-duty rotation handoff, and saved settings remain protected. VieriCodex and stock Questionable loaded together are a conflict before any quest IPC invocation; stock becomes the automatic selection only after the fork is disabled.
30. Progression provider discovery is read-only and capability-based. The initial quest contract requires `IsRunning`, `StartSingleQuest`, and `Stop`; the initial duty contract requires `ContentHasPath`, `Run`, `IsStopped`, and `Stop`. Discovery never invokes those members. Two ready implementations for one role are a conflict, not an automatic preference, and a saved plan cannot imply permission to execute.
31. Migration is install-first and local to each computer. Nexus must be installed while predecessor configurations still exist, then create verified staging and independent Nexus working copies before the user disables a replaced Vieri product. A second user repeats the flow against their own local configurations and content IDs; no first-user state, secrets, or identifiers may be packaged or copied to them. The supported user procedure is maintained in `USER_MIGRATION_FLOW.md`.

## Upstream update workflow

Questionable, AutoDuty, Avarice, DelvUI, Wrath Combo, and other incorporated upstream work retain pinned provenance in `upstreams/source-lock.json`.

For every upstream update:

1. Fetch without changing the active Nexus source.
2. Record the old pin, candidate pin, release notes, file delta, and dependency/API changes.
3. Classify changes as upstream behavior, Vieri customization overlap, data-only update, IPC change, or packaging change.
4. Apply the update in the owning module only.
5. Reapply Vieri patches as explicit reviewable commits; never hide them in a bulk source replacement.
6. Run module contracts, saved incident replays, configuration migrations, legacy IPC tests, and clean-package validation.
7. Perform targeted in-game validation for the affected workflows.
8. Update the source lock and third-party notices together.
9. Publish only after the Nexus release gate passes.

Questionable quest/path data should remain isolated from the Nexus orchestration core so routine upstream data updates do not destabilize combat, communications, the HUD, or market modules.

Stock Questionable, stock AutoDuty, Boss Mod, vnavmesh, Lifestream, and comparable providers should be consumed only through narrow capability/version adapters. Compatible provider updates must require no Nexus source change. VieriCodex remains authoritative until Nexus owns its planners, policies, safety fixes, custom-route overlay, and UI; only then may stock Questionable become the ordinary quest executor. VieriAutoDuty remains authoritative until Nexus owns its custom route/travel, progression-loop, gear/inventory, maintenance, telemetry, command, and UI behavior and the stock duty provider passes parity; only then may the fork retire. Missing or changed capabilities fail closed and never trigger an automatic fallback that could duplicate active work.

## Rollback

Each migrated module keeps the pre-import backup and migration receipt. Rollback restores Nexus-owned settings from that receipt without deleting or rewriting the predecessor configuration. Discord keys, channel IDs, message IDs, and per-character settings are verified before the standalone source is retired.
